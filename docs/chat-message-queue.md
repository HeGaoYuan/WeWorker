# 对话输入队列

适用分支：dev-1.1.0。当前实现保留现有聊天布局，在输入框上方增加待发送列表。

## 使用方式

- 回复过程中仍可输入，Enter 或「排队」将消息和附件加入当前会话的队列。当前回复结束后，按顺序逐条发送。
- 每条待发送消息支持编辑正文、立即发送和删除。编辑期间暂缓发送该条消息；保存保留原顺序和附件，取消恢复原文。
- 「立即发送」将选中的消息作为补充指令送入当前模型会话；正在执行的工具正常结束，后续模型步骤读取补充内容。它不会触发停止，也不会另起一个并行聊天请求。若当前没有执行中的回复，则优先发送选中项。
- 补充消息显示在插入时已经输出的内容之后，后续回复接在其下方。插入前后的回复分别保存，切换会话或重载后仍保持顺序；较晚返回的工具结果更新原来的工具块。仅按有序事件流插入，避免 HTTP 回执先到造成错位或文字重复。
- 「停止」结束当前回复并暂停余下队列。点击「继续队列」才继续发送。错误、流意外中断或命令非零退出同样暂停队列。
- 列表支持收起和独立滚动；底部消息留白随输入区域高度调整。
- 切换会话后，原会话继续执行自己的队列；各会话相互独立。

## 行为参考与边界

Cursor 官方 Agent 文档区分排队与立即补充：排队等当前任务完成，Send now 在后续工具调用边界引导当前执行，不中断正在进行的操作。参考：https://cursor.com/docs/agent/overview 。Codex 的公开 CLI 实现也区分 pending steers 与 queued messages；这不是对其桌面端全部版本交互一致性的断言。参考：https://github.com/openai/codex/blob/main/codex-rs/tui/src/chatwidget/input_queue.rs 。

WeWorker 使用现有 Claude 流式输入会话实现补充指令，沿用当前模型、思考设置、权限和工具上下文。预热、上下文准备、确定性工具路由或网站探索agent接管期间可能不支持立即补充，此时明确提示并保留队列。Shell 命令可以排队，但不能作为模型补充指令注入；按原有终端方式停止命令。

队列及未保存的编辑只驻留在内存中，切换会话保留，关闭或重载应用后不恢复。已被服务端接受但执行失败的消息不会自动重发；未确认接受的消息保留，需用户检查对话后继续。流中的接受回执可用于在 HTTP 回复丢失时消除重复发送；若所有回执均丢失，不能保证用户手动重试不会重复，因此不自动重试。

## 验证

- 队列状态机、流完成判断、上下文压缩兼容、聊天端点锁、停止确认、补充指令结束竞态均有自动化测试。
- 真实 Claude CLI 配合隔离的本地模拟模型验证：工具执行不被中断，下一模型请求包含补充指令，只启动一个 CLI，关闭后清理进程。没有调用付费模型。
- Chrome 实际点击验证排队、编辑、删除、立即发送、附件、会话切换、停止/继续、长列表滚动、流中断与命令失败暂停；接口由隔离 fixture 提供。1440×1000 和 900×700 布局无页面错误。
- 未验证完整 Electron、真实模型端到端或跨平台安装包。

2026-10-20 插入位置修复验证：Backend 43 项、Renderer 28 项专项测试、Backend 类型检查、Renderer 构建与 JS 语法检查通过。内存数据库用例验证同毫秒消息顺序、连续插入、迟到工具结果和会话复用；Chrome 隔离接口实际点击验证 HTTP 回执先到、两次插队、工具详情、会话切换及整页刷新。此项不等同于真实模型端到端验收；旧版已合并保存的历史回复无法可靠恢复原始插入位置。
