# Adapter 状态清单

本清单记录 WeWorker 当前公开 Profile 与扩展兼容目录中的网站 Adapter。状态必须与实际代码一致；新增或移除 Adapter 时，需要同步更新本文件、根 README、官网说明和对应构建配置。

## 状态定义

| 状态 | 判定标准 |
| --- | --- |
| 已实现 | 仓库中存在可打包的 Adapter manifest、命令代码和必要运行文件，并已进入公开 Profile 或扩展注册表 |
| 开发中 | 已有实现草稿或迁移记录，但未达到可供用户稳定使用的标准 |
| 规划中 | 保留在产品方向中，当前仓库没有可用实现 |

`默认打包` 与 `默认启用` 是独立属性：已实现的 Adapter 也可能因认证方式、兼容性或发布策略而暂不进入默认安装包。

## 能力与风险边界

- Adapter 依赖目标网站当前页面、接口和账号状态，网站更新后可能需要同步维护。
- “已实现”表示仓库存在实现和构建入口，不保证目标网站在所有账号、地区和时间均保持兼容。
- 需要认证的 Adapter 使用浏览器现有登录状态，不应在代码、Issue、测试数据、截图或日志中保存真实账号、Cookie、Token 或用户隐私数据。
- 发送、发布、下单、支付、投递、删除、关注、点赞、收藏等具有外部影响的操作必须提供清晰的用户确认。
- 用户需要遵守目标网站的服务协议、自动化规则和所在地区适用法律。

## 状态更新规则

新增或推进 Adapter 的 Pull Request 应同时完成：

1. 添加或更新 `adapters/<adapter-id>/` 下的 manifest、命令代码、必要运行文件和 guidance。
2. 如需保留扩展直注入兼容能力，同步更新 `extension/adapters/<adapter-id>/` 与 `extension/adapters/index.json`。
3. 明确是否加入 `weworker/build-profile.json` 的默认公开 Profile。
4. 添加聚焦自动化测试，并使用脱敏的示例数据。
5. 完成本地 CLI/扩展加载验证，不得用“文件存在”代替功能验证。
6. 在本文件、根 README、官网说明和 `CHANGELOG.md` 中更新用户可见变化。

Adapter 开发和调试方式见 [浏览器扩展文档](../extension/README.md) 与 [WebCLI 文档](../webcli/README.md)。
