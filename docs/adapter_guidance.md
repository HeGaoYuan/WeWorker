# v2 Adapter 人工指导

v2 包中的 `manifest.json` 仍是工具、参数、执行方式与安全标记的权威来源。对于 Schema 和命令描述难以表达的人工经验，可以在包根目录放一个可选的 `guidance.md`。宿主会把它和当前有效包的命令清单一起派生到运行时 Skill；它不是独立 Skill，也不会从旧 `extension/adapters` 目录读取。包摘要覆盖该文件，更新后须重新刷新 Skill。

`guidance.md` 适合记录工具选择、组合调用顺序、业务术语、结果字段解释、登录与页面前置条件、失败后的恢复方式。不要复制自动生成的工具列表、JSON Schema、旧命令名或测试样本。只引用当前包真实存在的命令；后台 API 与页面命令的前置条件应分别说明。字段的标准值、枚举、必填条件仍写在 Schema；需要确定性转换的业务别名应由该 Adapter 的命令实现处理，不能只依赖模型读懂指导。

`manifest.discovery_terms` 可选，最多 16 个短语，用于运行时 Skill 的发现描述。例如用户说“查待办”，但 Adapter 的站点名不直观时，把该说法加入发现词。发现词帮助模型找到 Skill，不会改变工具路由或参数。`guidance.md` 限 20 KB UTF-8 Markdown，不允许 Skill frontmatter；`SKILL.md`、`SKILL.generated.md` 和旧知识文件仍禁止进入 v2 包。

迁移旧 Skill 时逐条核对当前命令、接口和安全标记。过时的命令、错误的页面前置条件、未经验证的返回值推断和绕过写操作确认的提示都不要搬入。对仍有效的术语和调用经验写入包指导；对可执行约束增加命令实现或测试。验证至少覆盖包校验、生成 Skill 中的指导、有效包摘要变化，以及关键业务参数和写操作确认。真实站点行为仍需在对应环境验收。
